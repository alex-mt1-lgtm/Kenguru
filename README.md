## Рейтинг и достижения

В меню аккаунта доступны общий тренировочный рейтинг и личные достижения. В рейтинге видны имена пользователей, баллы и число решённых задач. Участники с одинаковым числом баллов занимают одно место. Засчитывается ответ, выбранный к первому открытию разбора. Если он верный, 3, 4 или 5 баллов появляются после подтверждения сервером. Офлайн ответ хранится во вкладке до отправки. При конфликте действует история, уже принятая сервером. Достижения учитывают подтверждённые баллы, число и сложность решённых задач.

## Возможности
Выбор любой задачи и ответа; от трёх до девяти шагов с прямой навигацией; назад/далее; показ/пауза; повтор текущей задачи; переход к следующей. Адрес меняется при выборе задачи, поэтому адрес страницы можно скопировать и открыть напрямую. Автопоказ не проходит мимо первого шага без самостоятельного выбора. Анимация обновляется через requestAnimationFrame по прошедшему времени, SVG-элементы обновляются без замены всего кадра. Пожарный идёт с постоянной скоростью, а второй отрезок продолжает первый без повторного старта. Пауза сохраняет точное положение и останавливает автоматические переходы; скрытие вкладки также включает паузу. Стрелки переключают шаги, пробел на фоне — показ/пауза. Адаптивная раскладка, крупный текст условия, фокус клавиатуры, SVG-подписи и оригиналы всех 684 задач.

## Самостоятельное решение на схеме
Панель «Твоя схема»: закрашивание клеток протягиванием, карандаш, прямая линия, лестница с перекладинами, выбор цвета, ластик, отмена и очистка. Можно рисовать пальцем или мышью. Очистку также можно отменить. Пометки хранятся отдельно для каждой задачи и шага; для задачи №1 — ещё и для каждого варианта А–Д. В первом шаге №1 можно выбрать рисунок без сетки и рисовать на нём; закрашивание клеток доступно после перехода к разбору. Переключатель А–Д меняет рабочую схему независимо от выбранного ответа. Пометки не меняют исходную схему или официальный ответ. Хранятся в памяти текущей страницы; после перезагрузки сбрасываются.

В задаче №10 ученик сам заполняет пустую таблицу предпочтений и распределяет фрукты. Дети перечислены в порядке условия, а не в порядке решения. Проверка не подставляет отметки, не убирает варианты автоматически и не выбирает ответ про Борю. Схема сохраняется при переходах, «Повтор» очищает её.

## Размещение на olympiads.pro

GitHub Actions сверяет собранные уроки, запускает тесты JavaScript и проверяет аккаунты на PHP с временной SQLite и тестовой почтой. После проверок он создаёт выпуск в ветке `olympiads`. Планировщику Рег.ру достаточно доступа на чтение этой публичной ветки.

Старый `olympiads-sync.sh` совместим с новым форматом. Он копирует ресурсы в `/_releases/<версия>/` перед корневыми страницами. Страницы загружают сценарии, наборы задач и рисунки из своего каталога и уже ограничивают загрузки через CSP в HTML. В ветке выпуска сохранены прежние ресурсы для уже открытых страниц со старыми адресами файлов. Корневой `.htaccess` отсутствует в ветке выпуска, поэтому старый установщик сохраняет правила хостинга. У старого варианта обе страницы и PHP переключаются по очереди.

Чтобы переключать страницы и PHP одним действием, замените содержимое `~/olympiads-sync.sh` актуальной версией из `scripts/`. Задание ispmanager по-прежнему запускает `/bin/bash "$HOME/olympiads-sync.sh"` каждые пять минут. Первые два аргумента при необходимости задают каталог сайта и закрытый каталог состояния. Значения по умолчанию — `$HOME/www/olympiads.pro` и `$HOME/.olympiads-deploy`.

Новый скрипт устанавливает полный комплект в `/_releases/<коммит>/`, затем атомарно заменяет свой блок в корневом `.htaccess`. Для этого Apache должен разрешать `mod_rewrite` и `mod_headers` через `.htaccess`. Для посетителей остаются адреса `/#zadacha=…`, `/archive.html` и `/api/auth.php`. После первого запуска проверьте целевой выпуск на этих адресах, действующий переход с HTTP на HTTPS и заголовки `Strict-Transport-Security`, `Content-Security-Policy` и `X-Frame-Options` на HTTPS. Заголовок HSTS начинает действовать на 300 секунд.

Если Git на хостинге пишет `packfile cannot be mapped` или `Out of memory` при получении выпуска, текущий установщик читает pack-файлы окнами по 1 МиБ и ограничивает кеш и число потоков. Для уже установленного старого скрипта те же настройки можно один раз сохранить в его локальном репозитории. Следующий запуск планировщика применит их при получении и распаковке выпуска.

```bash
repo="$HOME/.olympiads-deploy/repository"
git -C "$repo" config core.packedGitWindowSize 1m
git -C "$repo" config core.packedGitLimit 8m
git -C "$repo" config core.deltaBaseCacheLimit 2m
git -C "$repo" config pack.threads 1
```

Для просмотра установленных комплектов, возврата на выбранный коммит выпуска и возобновления обновлений используйте команды ниже. `rollback legacy` возвращает сохранённые корневые страницы без управляемого блока Apache. При откате очередной запуск cron оставляет закреплённую версию до `resume`.

```bash
site="$HOME/www/olympiads.pro"
state="$HOME/.olympiads-deploy"
bash "$HOME/olympiads-sync.sh" "$site" "$state" list
bash "$HOME/olympiads-sync.sh" "$site" "$state" rollback COMMIT
bash "$HOME/olympiads-sync.sh" "$site" "$state" resume
```

Комплект с PDF занимает примерно 234 МиБ. После просмотра `list` команда `prune` может удалить неизменённые комплекты нового установщика через 30 суток после их последнего снятия с публикации. Она сохраняет активный, предыдущий и закреплённый выпуски, каталоги старого установщика и изменённые каталоги. Конфигурация и база аккаунтов остаются за пределами корня сайта.

### Аккаунты и восстановление пароля

Для серверных аккаунтов на Рег.ру нужен PHP 8.2 или новее с `pdo_sqlite` и `mbstring`. В ispmanager создайте почтовый ящик `noreply@olympiads.pro` для писем восстановления. При необходимости настройте этот адрес как отправителя для PHP mail и включите DKIM для почтового домена.

Однократно выполните `scripts/init-reg-ru-accounts.sh` с абсолютным путём к домашней папке пользователя хостинга. Скрипт создаёт `olympiads-config.php` рядом с папкой `www`. При первом обращении API создаёт закрытую базу SQLite в `.olympiads-auth/`. PHP должен иметь права чтения конфигурации и записи в этот каталог вне корня сайта. Проверка готовности доступна по `GET /api/auth.php?action=session`.

Аккаунт синхронизирует ответы, открытые разборы, текущий шаг и рейтинг между устройствами. В гостевом режиме достаточно открыть задачу. Новые пользователи подтверждают почту по ссылке в письме, прежде чем использовать восстановление пароля. Ранее зарегистрированные пользователи сохраняют действующий способ восстановления. Изменение имени и почты и удаление профиля доступны в разделе «Данные аккаунта». Сценарии проверяются командой `PHP_BINARY=php python3 tests/account-api-test.py -v` с тестовой доставкой письма.
